# Архитектура и стек

## Стек

| Часть | Выбор | Причина |
|---|---|---|
| Оболочка | Tauri 2 | Маленький установщик (около 10 МБ), сборки для Windows, macOS и Linux |
| Интерфейс | React + TypeScript + Vite | Тот же код позже станет веб-версией |
| Стили | Tailwind CSS с токенами дизайна | Готовый дизайн подключается заменой токенов |
| Состояние | Zustand | Простое, без лишнего кода |
| Маршруты | React Router (hash-режим) | Экранов немного, сложный роутер не нужен |
| Движок печати | Чистый TypeScript без React и Tauri | Легко тестировать, переносится в веб |
| Хранилище | SQLite через `tauri-plugin-sql` | Вся история уроков локально, легко экспортировать |
| Переводы | i18next | Русский и английский с первого дня |
| Графики | Собственные SVG-компоненты | Графиков мало, дизайн будет свой |
| Шрифт | JetBrains Mono, встроен в приложение | Моноширинный с кириллицей, работает без сети |
| Тесты | Vitest + Testing Library | Быстрые модульные тесты движка и компонентов |
| Сборка и релизы | GitHub Actions + `tauri-action` | Установщики для трёх ОС при создании тега |
| Обновления | `tauri-plugin-updater` + GitHub Releases | Бесплатно, без своего сервера |

### Почему не другое

| Вариант | Почему нет |
|---|---|
| Electron | Установщик больше 100 МБ, больше расход памяти. Плюс — одинаковый движок на всех ОС; если WebView на Linux создаст проблемы, переход возможен без переписывания интерфейса |
| Flutter | Свой язык и свой рендеринг; веб-версия на нём хуже подходит для текста |
| Нативное приложение (.NET, Qt) | Отдельная разработка под каждую ОС, нет общей базы с будущим вебом |

```
│  │  ├─ textgen/        словарь, буквенная модель, сборка текста урока
│  │  └─ motivation/     дневная цель, серия, достижения
│  ├─ content/           данные: раскладки, курсы, словари, модели
│  ├─ storage/           интерфейс хранилища и реализация для SQLite
│  ├─ ui/                React: экраны, компоненты, тема
│  ├─ i18n/              ru.json, en.json
│  └─ app/               маршруты, состояние, запуск
├─ src-tauri/            оболочка на Rust: окно, плагины, миграции БД
├─ tools/                скрипты сборки словарей и буквенных моделей
└─ tests/                общие тестовые данные и «синтетический наборщик»
```

### Главное правило

`engine/` не импортирует ничего из `ui/`, `storage/`, `app/` и Tauri. Это проверяется правилом ESLint. Движок получает данные на вход и возвращает результат; время и случайность передаются снаружи, поэтому тесты детерминированы.

Пока всё лежит в одном пакете. Когда появится веб-версия, `engine/` и `content/` выносятся в отдельные пакеты без переписывания.

## Движок

### Основные типы

```ts
type KeyCode = string;   // KeyboardEvent.code: "KeyA", "Semicolon", "Space"

type Finger =
  | 'lPinky' | 'lRing' | 'lMiddle' | 'lIndex'
  | 'thumb'
  | 'rIndex' | 'rMiddle' | 'rRing' | 'rPinky';

interface Layout {
  id: 'en-us-qwerty' | 'ru-jcuken';
  language: 'en' | 'ru';
  keys: Record<KeyCode, { base: string; shift: string }>;
}

interface Geometry {
  id: 'ansi' | 'iso';
  rows: { code: KeyCode; width: number; gap: number }[][];  // gap — пустое место перед клавишей
  fingers: Record<KeyCode, Finger>;
  home: Record<Finger, KeyCode>;                             // где лежит палец в основной позиции
  homing: KeyCode[];                                         // клавиши с выступами: F и J
}

interface Course {
  layoutId: Layout['id'];
  // start — клавиши, открытые с первого урока; order — группы клавиш в порядке открытия.
  // В файле группа записана строкой: ["dk", "sl", "a", "e", …]
  stages: { id: string; start: string[]; order: string[][] }[];
}

interface KeyStat {
  hits: number;
  misses: number;
  timeEma: number | null;
  accEma: number | null;
  bestConfidence: number;
}
```

Раскладка (какой символ на клавише) и геометрия (где клавиша и какой палец) хранятся отдельно. Поэтому новая раскладка — это один файл данных и один файл курса.

В файле геометрии пальцы записаны списками клавиш, как в таблице зон из [методики](learning-method.md); при загрузке они превращаются в `fingers`. Файлы данных проверяются при запуске приложения: ошибка в файле сразу видна.

Числовые параметры обучения лежат в одном файле — `src/engine/params.ts`.

### Обработка ввода

```ts
function toInput(e: KeyboardEvent, layout: Layout, mode: 'emulate' | 'system') {
  if (e.repeat || e.isComposing || e.ctrlKey || e.altKey || e.metaKey) return null;
  const char = mode === 'emulate'
    ? layout.keys[e.code]?.[e.shiftKey ? 'shift' : 'base']
    : e.key.length === 1 ? e.key : undefined;
  return char === undefined ? null : { char, code: e.code, time: e.timeStamp };
}
```

- **Режим эмуляции (по умолчанию).** Символ определяется по физической клавише (`event.code`) и таблице раскладки. Урок на русском работает, даже если в системе включена английская раскладка.
- **Режим системной раскладки.** Символ берётся из `event.key`. Если нажата верная физическая клавиша, но пришёл символ другой раскладки, это не ошибка: показывается подсказка «переключите раскладку».
- **Время** берётся из `event.timeStamp`, а не из `Date.now()`: оно точнее.
- **Автоповтор** (`event.repeat`) и сочетания с Ctrl / Alt / Meta игнорируются.
- **Caps Lock** определяется через `getModifierState('CapsLock')`, показывается предупреждение.

### Автомат урока

```
готов ──первое нажатие──▶ идёт ──последний знак──▶ завершён
                           │  ▲
        бездействие 5 с,   ▼  │  любая клавиша
        потеря фокуса, Esc пауза
```

- Клавиша, которая снимает паузу, не набирается: она только продолжает урок.
- Перерыв между нажатиями 5 с и больше считается паузой, даже если таймер бездействия не успел сработать. Так время урока не зависит от точности таймера.
- Состояние урока не меняется на месте: каждое нажатие возвращает новое состояние. Это упрощает тесты и отрисовку.

На выходе урока — результат: длительность, скорость, точность и статистика по каждой клавише (верные нажатия, ошибки, сумма времени, какие клавиши нажимались вместо нужной).

### Остальные модули

| Модуль | Вход | Выход |
|---|---|---|
| `stats` | Нажатия урока по порядку, прежняя статистика клавиш | Новая статистика клавиш |
| `progress` | Статистика клавиш, этап курса, число открытых групп, параметры | Открытые и закрытые клавиши, фокусная клавиша, что мешает открыть следующую группу |
| `textgen` | Открытые клавиши, фокусная клавиша, словарь, модель, список запрещённых слов, генератор случайных чисел | Текст урока |
| `layout/reach` | Геометрия, клавиша | Какой палец и куда тянется от основной позиции (для карточки новой клавиши) |
| `motivation` | История дней, результат урока | Прогресс цели, серия, новые достижения |

Пробел есть в каждом уроке и копит свою статистику, но в курс не входит: он не бывает фокусной клавишей и не задерживает открытие следующей.

Состояние приложения (статистика клавиш, число открытых групп, текущий урок) живёт в `src/app/practice.ts`. В конце урока оно обновляет статистику, проверяет открытие клавиш и сохраняет урок в хранилище, не дожидаясь записи.

Формулы и правила описаны в [методике обучения](learning-method.md).

### Сборка словарей

Команда `pnpm content:build` запускает `tools/build-content.ts`. Скрипт берёт исходные частотные списки из `tools/sources/` и создаёт для каждого языка `words.json`, `ngrams.json` и `blocklist.json`:

1. Оставляет слова только из букв языка, длиной 2–10, в нижнем регистре.
2. Для русского заменяет «ё» на «е».
3. Убирает нежелательные слова (`blocklist.json`) и не-слова: междометия и сокращения (`tools/sources/exclude/`).
4. Двухбуквенные слова берёт только из первых 600 строк источника: ниже в списке среди них в основном сокращения (`lt`, `dr`).
5. Оставляет первые 10 000 слов по частоте.
6. Строит буквенную модель: какие буквы идут после каждой пары букв, с отметками начала (`^`) и конца (`$`) слова. Каждое слово считается один раз.

Слово запрещено, если оно есть в `blocklist.json` или начинается с запрещённого слова из 4 и более букв. Короткие запрещённые слова совпадают только целиком, поэтому «ass» не задевает «class». То же правило проверяет псевдослова во время урока.

Готовые файлы хранятся в репозитории, приложение при работе ничего не пересчитывает.

**Источники:** частотные списки [FrequencyWords](https://github.com/hermitdave/FrequencyWords) по субтитрам OpenSubtitles 2018 (CC BY-SA 4.0) и списки нежелательных слов [LDNOOBW](https://github.com/LDNOOBW/List-of-Dirty-Naughty-Obscene-and-Otherwise-Bad-Words) (CC BY 4.0). Закреплённые версии, лицензии и что из них получается — в `tools/sources/README.md`. Словари приложения — переработка FrequencyWords, поэтому они распространяются под CC BY-SA 4.0; на лицензию кода это не влияет. Авторство нужно указать в разделе «О программе» (задача 6.10).

## Хранилище

Интерфейс `Storage` описан в `src/storage/types.ts`. Реализации:

| Реализация | Где используется |
|---|---|
| SQLite (`src/storage/sqlite.ts`) | Настольное приложение. База `keyed.db` в папке данных приложения |
| В памяти с копией в `localStorage` (`src/storage/memory.ts`) | Интерфейс в обычном браузере (`pnpm dev`) и тесты |
| IndexedDB | Веб-версия, позже |

```sql
profile         (id, name, created_at)
settings        (profile_id, key, value)                    -- value в JSON
lesson          (id, profile_id, layout_id, stage, started_at, duration_ms,
                 length, errors, cpm, accuracy, samples_json)
key_stat        (profile_id, layout_id, key, hits, misses, time_ema, acc_ema,
                 best_confidence, updated_at)
course_progress (profile_id, layout_id, stage, opened, updated_at)  -- сколько групп открыто
daily           (profile_id, date, active_ms, lessons, chars, goal_met, freeze_used)
achievement     (profile_id, id, level, unlocked_at)
```

- В первой версии профиль один, но `profile_id` есть во всех таблицах. Несколько профилей и синхронизация добавятся без смены схемы.
- `samples_json` — все нажатия урока по порядку: знак, время, неверные знаки. Из них можно полностью пересчитать `key_stat`. Это страховка при смене формул.
- Миграции лежат в `src-tauri/migrations/` и выполняются `tauri-plugin-sql` при открытии базы. Выпущенную миграцию не меняют, только добавляют новые.
- Плагин выполняет каждый запрос отдельно, поэтому урок сохраняется не одной транзакцией. Сначала записывается урок, потом статистика и прогресс: если запись оборвётся, статистику можно восстановить из уроков.
- Если базу не удалось открыть или запись не прошла, приложение продолжает работать с данными в памяти и показывает предупреждение.
- Тесты проверяют SQLite-реализацию на настоящем SQLite (`node:sqlite`) с той же миграцией, что и в приложении.
- Экспорт и импорт — один JSON-файл со всеми таблицами.

## Оболочка Tauri

Rust-часть минимальная: окно и плагины.

| Плагин | Зачем |
|---|---|
| `sql` (SQLite) | Хранилище |
| `updater` | Обновления |
| `notification` | Напоминания |
| `window-state` | Запоминать размер и положение окна |
| `single-instance` | Не запускать вторую копию |

Строгая политика безопасности содержимого (CSP), загрузка внешних ресурсов запрещена. Права плагинов — только необходимые.

## Интерфейс

- Компоненты получают данные из хранилища состояния и не содержат логики обучения.
- **Скорость отклика.** От нажатия до отрисовки — не дольше одного кадра (16 мс). При нажатии обновляются только два знака и две клавиши, а не весь текст.
- Курсор двигается через CSS-трансформацию.
- Все цвета, шрифты и отступы заданы токенами. Светлая и тёмная тема — два набора значений.
- Все строки интерфейса — только через i18next, без текста в коде.
- **Графики** (экран статистики) — свои SVG-компоненты в `src/ui/charts/`. Скорость и точность — два отдельных графика, без второй оси. У каждого графика есть подсказка при наведении и с клавиатуры (стрелки) и таблица с теми же данными. Тепловая карта клавиш — пять шагов одного синего цвета; шкала проверена на контраст и различимость шагов в обеих темах.

## Тестирование

| Уровень | Что проверяется |
|---|---|
| Модульные тесты движка | Ввод, автомат урока, метрики, формулы уверенности, открытие клавиш, генератор текста (с фиксированным зерном) |
| «Синтетический наборщик» | `tests/syntheticTypist.ts` имитирует ученика, который со временем печатает быстрее и точнее, и проходит весь английский курс (`tests/course.test.ts`). Проверяет, что все буквы открываются, на одну клавишу уходит не больше 40 уроков, в тексте нет закрытых букв и фокусная клавиша есть хотя бы в половине слов |
| Тесты хранилища | Обе реализации проходят один набор тестов; SQLite — на настоящей базе с миграцией приложения |
| Тесты компонентов | Состояния знака, клавиши, экран практики, карточка новой клавиши, главная, статистика |
| Проверка содержания | В словарях нет запрещённых слов и чужих букв; каждая буква раскладки есть в курсе |
| Ручная проверка | Windows, macOS, Linux; клавиатуры ANSI и ISO |

CI на каждый коммит: линтер, проверка типов, тесты.
