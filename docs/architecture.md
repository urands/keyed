# Архитектура и стек

## Стек

| Часть | Выбор | Причина |
|---|---|---|
| Оболочка | Tauri 2 | Маленький установщик (около 10 МБ), сборки для Windows, macOS и Linux |
| Интерфейс | React + TypeScript + Vite | Тот же код позже станет веб-версией |
| Стили | Tailwind CSS с токенами дизайна | Готовый дизайн подключается заменой токенов |
| Состояние | Zustand | Простое, без лишнего кода |
| Маршруты | React Router (hash-режим) | Экранов немного, сложный роутер не нужен |
| Движок печати | Чистый TypeScript без React и Tauri | Легко тестировать, переносится в веб |
| Хранилище | SQLite через `tauri-plugin-sql` | Вся история уроков локально, легко экспортировать |
| Переводы | i18next | Русский и английский с первого дня |
| Графики | Собственные SVG-компоненты | Графиков мало, дизайн будет свой |
| Шрифты | JetBrains Mono (текст урока) и Inter (интерфейс), встроены в приложение | С кириллицей, работают без сети |
| Значки | Lucide (`lucide-react`) | Единый стиль, в сборку попадают только нужные |
| Тесты | Vitest + Testing Library | Быстрые модульные тесты движка и компонентов |
| Сборка и релизы | GitHub Actions + `tauri-action` | Установщики для трёх ОС при создании тега |
| Обновления | `tauri-plugin-updater` + GitHub Releases | Бесплатно, без своего сервера |
| Страница загрузки | GitHub Pages из папки `site/` | Бесплатно, в том же репозитории |

### Почему не другое

| Вариант | Почему нет |
|---|---|
| Electron | Установщик больше 100 МБ, больше расход памяти. Плюс — одинаковый движок на всех ОС; если WebView на Linux создаст проблемы, переход возможен без переписывания интерфейса |
| Flutter | Свой язык и свой рендеринг; веб-версия на нём хуже подходит для текста |
| Нативное приложение (.NET, Qt) | Отдельная разработка под каждую ОС, нет общей базы с будущим вебом |

### Главное правило

`engine/` не импортирует ничего из `ui/`, `storage/`, `app/` и Tauri. Это проверяется правилом ESLint. Движок получает данные на вход и возвращает результат; время и случайность передаются снаружи, поэтому тесты детерминированы.

Пока всё лежит в одном пакете. Когда появится веб-версия, `engine/` и `content/` выносятся в отдельные пакеты без переписывания.

## Движок

### Основные типы

```ts
type KeyCode = string;   // KeyboardEvent.code: "KeyA", "Semicolon", "Space"

type Finger =
  | 'lPinky' | 'lRing' | 'lMiddle' | 'lIndex'
  | 'thumb'
  | 'rIndex' | 'rMiddle' | 'rRing' | 'rPinky';

interface Layout {
  id: 'en-us-qwerty' | 'ru-jcuken';
  language: 'en' | 'ru';
  keys: Record<KeyCode, { base: string; shift: string }>;
}

interface Geometry {
  id: 'ansi' | 'iso';
  rows: { code: KeyCode; width: number; gap: number }[][];  // gap — пустое место перед клавишей
  fingers: Record<KeyCode, Finger>;
  home: Record<Finger, KeyCode>;                             // где лежит палец в основной позиции
  homing: KeyCode[];                                         // клавиши с выступами: F и J
}

interface Course {
  layoutId: Layout['id'];
  // start — клавиши, открытые с первого урока этапа; order — группы клавиш в порядке открытия.
  // В файле группа записана строкой: ["dk", "sl", "a", "e", …]
  stages: {
    id: string;
    kind: 'letters' | 'capitals' | 'punctuation' | 'digits' | 'free';  // как строится текст
    start: string[];
    order: string[][];
    intro: number;        // сколько первых групп входят в стартовый набор
    optional: string[];   // клавиши, которые включает настройка («ё»)
  }[];
}

interface KeyStat {
  hits: number;
  misses: number;
  timeEma: number | null;
  accEma: number | null;
  bestConfidence: number;
}
```

Раскладка (какой символ на клавише) и геометрия (где клавиша и какой палец) хранятся отдельно. Поэтому новая раскладка — это один файл данных и один файл курса.

В файле геометрии пальцы записаны списками клавиш, как в таблице зон из [методики](learning-method.md); при загрузке они превращаются в `fingers`. Файлы данных проверяются при запуске приложения: ошибка в файле сразу видна.

Числовые параметры обучения лежат в одном файле — `src/engine/params.ts`.

### Обработка ввода

```ts
function toInput(e: KeyboardEvent, layout: Layout, mode: 'emulate' | 'system') {
  if (e.repeat || e.isComposing || e.ctrlKey || e.altKey || e.metaKey) return null;
  const char = mode === 'emulate'
    ? layout.keys[e.code]?.[e.shiftKey ? 'shift' : 'base']
    : e.key.length === 1 ? e.key : undefined;
  return char === undefined ? null : { char, code: e.code, time: e.timeStamp };
}
```

- **Режим эмуляции (по умолчанию).** Символ определяется по физической клавише (`event.code`) и таблице раскладки. Урок на русском работает, даже если в системе включена английская раскладка.
- **Режим системной раскладки.** Символ берётся из `event.key`. Если пришёл символ, которого нет в раскладке урока (латинская `f` в русском уроке), это не ошибка: нажатие не засчитывается, показывается подсказка «переключите раскладку». Символ, который в раскладке урока есть, считается обычным нажатием.
- **Время** берётся из `event.timeStamp`, а не из `Date.now()`: оно точнее.
- **Автоповтор** (`event.repeat`) и сочетания с Ctrl / Alt / Meta игнорируются.
- **Caps Lock** определяется через `getModifierState('CapsLock')` при каждом нажатии и отпускании клавиши, показывается предупреждение.

### Автомат урока

```
готов ──первое нажатие──▶ идёт ──последний знак──▶ завершён
                           │  ▲
        бездействие 5 с,   ▼  │  любая клавиша
        потеря фокуса, Esc пауза
```

- Клавиша, которая снимает паузу, не набирается: она только продолжает урок.
- Перерыв между нажатиями 5 с и больше считается паузой, даже если таймер бездействия не успел сработать. Так время урока не зависит от точности таймера.
- Состояние урока не меняется на месте: каждое нажатие возвращает новое состояние. Это упрощает тесты и отрисовку.

На выходе урока — результат: длительность, скорость, точность и статистика по каждой клавише (верные нажатия, ошибки, сумма времени, какие клавиши нажимались вместо нужной).

### Остальные модули

| Модуль | Вход | Выход |
|---|---|---|
| `stats` | Нажатия урока по порядку, прежняя статистика клавиш | Новая статистика клавиш |
| `progress` | Статистика клавиш, этап курса, число открытых групп, параметры | Открытые и закрытые клавиши, фокусная клавиша, что мешает открыть следующую группу |
| `progress/courseState` | Курс, открытые группы по этапам, статистика клавиш | Текущий этап, пройденные этапы, все открытые знаки, прогресс этапа. Свободная практика получает все клавиши этапов до неё |
| `textgen` | Вид этапа, открытые знаки, фокусная клавиша, словарь, модель, список запрещённых слов, сокращения и слова с дефисом, генератор случайных чисел | Текст урока (`buildCourseText`; этап букв — `buildLessonText`) |
| `layout/reach` | Геометрия, клавиша | Какой палец и куда тянется от основной позиции (для карточки новой клавиши); какой Shift нажимать (`shiftFor`, всегда другой рукой) |

Время знака с Shift сравнивается с целью, умноженной на `shiftAllowance` (1,25): функция запаса строится по раскладке (`shiftAllowance(layout, …)`) и передаётся в `applySamples`, `evaluateStage`, `advanceStage` и `courseState`.
| `motivation` | Дни, уроки, показатели прогресса, сохранённые достижения | День с учётом урока, серия и заморозки, итоги и рекорды, неделя к неделе, новые уровни достижений, главный вывод урока |

Пробел есть в каждом уроке и копит свою статистику, но в курс не входит: он не бывает фокусной клавишей и не задерживает открытие следующей.

Состояние приложения (раскладка, статистика клавиш, открытые группы по этапам, место в курсе, тренируемая клавиша, текущий урок) живёт в `src/app/practice.ts`. В конце урока оно обновляет статистику, проверяет открытие клавиш текущего этапа, переход к следующему этапу и сохраняет урок в хранилище, не дожидаясь записи. Урок записывается с id этапа, на котором он пройден.

Состояние каждой клавиши всего курса для экранов «Курс», «Главная» и «Статистика» считает `src/app/courseView.ts`.

Всё, что нужно для одной раскладки — раскладка, курс (с «ё» или без, по настройке), словарь и буквенная модель, запас времени для Shift, — собрано в `src/app/layouts.ts`. Прогресс у каждой раскладки свой: при переключении текущий прогресс остаётся в памяти, а прогресс другой раскладки берётся из памяти или загружается из хранилища. Выбранная раскладка хранится в настройках; без сохранённого выбора она следует языку интерфейса.

Геометрия клавиатуры (ANSI или ISO) выбирается в настройках: `geometryFor(id)` и хук `useGeometry()` в `src/app/layouts.ts`. Раскладки от геометрии не зависят: лишняя клавиша ISO у левого Shift (`IntlBackslash`) показывает знаки клавиши `\` и в уроках не участвует.

Настройки (`src/app/settings.ts`): язык, тема, раскладка, единицы скорости (`auto` — зн/мин для русской, WPM для английской), режим ввода, тип клавиатуры, строгий режим, буква «ё», целевая скорость (100–400 с шагом 25), длина урока (60 / 120 / 200 / 300), показ клавиатуры и рук, размер текста, «меньше движения», дневная цель, напоминания и их время, звуки и громкость, автопроверка обновлений и отметка «мастер первого запуска пройден». Все сохраняются в хранилище при каждом изменении. Целевая скорость и длина урока попадают в движок через `learningParams()`: это `DEFAULT_PARAMS` с двумя значениями из настроек. При смене скорости прогресс пересчитывается, при смене длины — строится новый текст.

Мастер первого запуска (`src/ui/welcome/WelcomeWizard.tsx`) показывается вместо всего приложения, пока `onboarded` не включена. При запуске она включается сама, если в хранилище уже есть уроки. Уровень «печатаю вслепую» открывает все буквы сразу (`openAllLetters` в `practice.ts`, запись через `saveOpened`).

### Мотивация

Состояние мотивации живёт в `src/app/motivation.ts`. Практика передаёт туда каждый законченный урок, а мотивация обновляет:

- **день** урока — по местной дате начала: время набора, уроки, знаки, отметку «цель выполнена». Отметка ставится, когда цель достигнута, и потом не снимается, даже если цель увеличить. Сегодняшний день оценивается по текущей цели;
- **итоги** по всем урокам: всего уроков, знаков и времени, лучшая скорость, уроки без ошибок, серия точных уроков, рекорды по раскладкам;
- **достижения**: показатели считаются из итогов, лучшей серии и прогресса всех раскладок, новые уровни сохраняются и показываются плашкой. Сохранённый уровень никогда не уменьшается.

**Серия не хранится** — она каждый раз пересчитывается из дней с выполненной целью (`engine/motivation/streak.ts`). День за днём: выполненный день продлевает серию, каждые 7 дней дают заморозку (не больше двух), пропущенный день тратит заморозку, а без неё серия обрывается. Сегодняшний день пропуском не считается. Поэтому колонка `freeze_used` в таблице `daily` не заполняется: какие дни закрыты заморозкой, видно из пересчёта. Правила заморозок — в `src/engine/params.ts`, условия достижений — в `src/content/achievements.json`.

При запуске загружаются прогресс всех раскладок, дни, вся история уроков (без нажатий) и достижения. Достижения, заработанные раньше (например, до появления фазы 4), выдаются тихо, без плашек.

**Напоминания** (`src/app/reminders.ts`) проверяют раз в 30 секунд: включены ли они, настало ли время, выполнена ли цель, напоминали ли сегодня. Уведомление отправляет `tauri-plugin-notification`. Напоминание приходит, только пока KeyEd запущен (можно свёрнутым).

**Звуки** клавиш и ошибки создаются через Web Audio API, без звуковых файлов. По умолчанию выключены.

Формулы и правила описаны в [методике обучения](learning-method.md).

### Сборка словарей

Команда `pnpm content:build` запускает `tools/build-content.ts`. Скрипт берёт исходные частотные списки из `tools/sources/` и создаёт для каждого языка `words.json`, `ngrams.json` и `blocklist.json`:

1. Оставляет слова только из букв языка, длиной 2–10, в нижнем регистре.
2. Для русского заменяет «ё» на «е». Второй вариант русского словаря и модели (`words-yo.json`, `ngrams-yo.json`) сохраняет «ё».
3. Убирает нежелательные слова (`blocklist.json`) и не-слова: междометия, сокращения и обрывки английских сокращений вроде `doesn`, `didn` (`tools/sources/exclude/`), записи с тремя одинаковыми буквами подряд (`ааа`, `mmm`).
4. Двухбуквенные слова берёт только из первых 600 строк источника: ниже в списке среди них в основном сокращения (`lt`, `dr`).
5. Оставляет первые 10 000 слов по частоте.
6. Строит буквенную модель: какие буквы идут после каждой пары букв, с отметками начала (`^`) и конца (`$`) слова. Каждое слово считается один раз.

Слово запрещено, если оно есть в `blocklist.json` или начинается с запрещённого слова из 4 и более букв. Короткие запрещённые слова совпадают только целиком, поэтому «ass» не задевает «class». То же правило проверяет псевдослова во время урока.

Готовые файлы хранятся в репозитории, приложение при работе ничего не пересчитывает.

**Источники:** частотные списки [FrequencyWords](https://github.com/hermitdave/FrequencyWords) по субтитрам OpenSubtitles 2018 (CC BY-SA 4.0) и списки нежелательных слов [LDNOOBW](https://github.com/LDNOOBW/List-of-Dirty-Naughty-Obscene-and-Otherwise-Bad-Words) (CC BY 4.0). Закреплённые версии, лицензии и что из них получается — в `tools/sources/README.md`. Словари приложения — переработка FrequencyWords, поэтому они распространяются под CC BY-SA 4.0; на лицензию кода это не влияет. Авторство нужно указать в разделе «О программе» (задача 6.10).

## Хранилище

Интерфейс `Storage` описан в `src/storage/types.ts`. Реализации:

| Реализация | Где используется |
|---|---|
| SQLite (`src/storage/sqlite.ts`) | Настольное приложение. База `keyed.db` в папке данных приложения |
| В памяти с копией в `localStorage` (`src/storage/memory.ts`) | Интерфейс в обычном браузере (`pnpm dev`) и тесты |
| IndexedDB | Веб-версия, позже |

```sql
profile         (id, name, created_at)
settings        (profile_id, key, value)                    -- value в JSON
lesson          (id, profile_id, layout_id, stage, started_at, duration_ms,
                 length, errors, cpm, accuracy, samples_json)
key_stat        (profile_id, layout_id, key, hits, misses, time_ema, acc_ema,
                 best_confidence, updated_at)
course_progress (profile_id, layout_id, stage, opened, updated_at)  -- сколько групп открыто
daily           (profile_id, date, active_ms, lessons, chars, goal_met, freeze_used)  -- freeze_used не заполняется: см. «Мотивация»
achievement     (profile_id, id, level, unlocked_at)
```

- В первой версии профиль один, но `profile_id` есть во всех таблицах. Несколько профилей и синхронизация добавятся без смены схемы.
- `samples_json` — все нажатия урока по порядку: знак, время, неверные знаки. Из них можно полностью пересчитать `key_stat`. Это страховка при смене формул.
- Миграции лежат в `src-tauri/migrations/` и выполняются `tauri-plugin-sql` при открытии базы. Выпущенную миграцию не меняют, только добавляют новые.
- Плагин выполняет каждый запрос отдельно, поэтому урок сохраняется не одной транзакцией. Сначала записывается урок, потом статистика и прогресс: если запись оборвётся, статистику можно восстановить из уроков.
- Если базу не удалось открыть или запись не прошла, приложение продолжает работать с данными в памяти и показывает предупреждение.
- Тесты проверяют SQLite-реализацию на настоящем SQLite (`node:sqlite`) с той же миграцией, что и в приложении.

### Экспорт, импорт и сброс

Экспорт — один JSON-файл (`src/storage/backup.ts`): `format: "keyed-backup"`, `version: 1`, время экспорта, настройки, все уроки с нажатиями, статистика клавиш и открытые группы по раскладкам, дни, достижения. Хранилище отдаёт и принимает эти данные методами `exportData` и `importData`; `resetProgress` удаляет уроки, статистику, прогресс курса, дни и достижения, а настройки оставляет.

- Файл проверяется целиком до того, как что-то будет изменено. Не JSON или чужой файл, файл более новой версии и повреждённая запись дают разные сообщения.
- Импорт заменяет всё: сначала очищает таблицы, потом вставляет строки пачками по 50 (плагин SQL отправляет каждый запрос отдельно, пачки заметно быстрее). Одной транзакцией это сделать нельзя, поэтому перед импортом стоит сделать экспорт — об этом говорит диалог подтверждения.
- После импорта и сброса окно перезагружается: все экраны берут данные из хранилища заново.
- В настольном приложении файл выбирается системным диалогом (`tauri-plugin-dialog`), а читается и пишется через `tauri-plugin-fs`. Глобального доступа к файлам у интерфейса нет: плагин диалога разрешает только выбранный путь. В обычном браузере файл скачивается и загружается через `<input type="file">`.

## Оболочка Tauri

Rust-часть минимальная: окно и плагины.

| Плагин | Зачем |
|---|---|
| `sql` (SQLite) | Хранилище |
| `updater` | Обновления |
| `process` | Перезапуск после установки обновления |
| `notification` | Напоминания |
| `dialog`, `fs` | Выбор файла и запись/чтение при экспорте и импорте |
| `opener` | Ссылки из «О программе» открываются в системном браузере |
| `window-state` | Запоминать размер и положение окна |
| `single-instance` | Не запускать вторую копию |

Строгая политика безопасности содержимого (CSP), загрузка внешних ресурсов запрещена. Права плагинов — только необходимые (`src-tauri/capabilities/default.json`): у `fs` только чтение и запись текстового файла, и только по пути, выбранному в диалоге; у `process` только перезапуск; у `opener` только открытие ссылки.

### Обновления

`src/app/updates.ts`. Через 5 секунд после запуска, если включена автопроверка, приложение запрашивает `https://github.com/urands/keyed/releases/latest/download/latest.json`. Это единственный сетевой запрос KeyEd. Если есть новая версия, показывается диалог (не во время урока); «Обновить и перезапустить» скачивает и ставит обновление, затем перезапускает приложение. Без сети автоматическая проверка молча ждёт следующего запуска, ручная («О программе») сообщает об ошибке.

Обновления подписаны ключом minisign: открытый ключ записан в `tauri.conf.json` (`plugins.updater.pubkey`), закрытый и его пароль хранятся в секретах репозитория `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, копия — у владельца вне репозитория. Без закрытого ключа выпустить обновление нельзя: установленные копии примут только подписанное им.

## Интерфейс

- Компоненты получают данные из хранилища состояния и не содержат логики обучения.
- **Скорость отклика.** От нажатия до отрисовки — не дольше одного кадра (16 мс). При нажатии обновляются только два знака и две клавиши, а не весь текст.
- Курсор двигается через CSS-трансформацию.
- Все цвета, шрифты и отступы заданы токенами (`src/ui/theme/tokens.css`). Светлая и тёмная тема — два набора значений одних и тех же токенов; тест `theme.test.ts` проверяет, что наборы совпадают и что каждая пара «текст — фон» даёт контраст не ниже 4,5:1 (WCAG AA), включая подписи на клавишах всех зон пальцев.
- «Меньше движения»: `settings-sync.ts` ставит `data-motion="reduce"` на `<html>`, если так выбрано в настройках или в системе, и CSS отключает переходы и анимации. Вспышка нажатой клавиши остаётся: она меняет только цвет.
- Всё основное работает с клавиатуры: видимая рамка фокуса у всех элементов, выбор вариантов на радиокнопках (стрелки), диалоги держат фокус внутри и закрываются по Esc.
- Все строки интерфейса — только через i18next, без текста в коде.
- **Графики** (экран статистики) — свои SVG-компоненты в `src/ui/charts/`. Скорость и точность — два отдельных графика, без второй оси. У каждого графика есть подсказка при наведении и с клавиатуры (стрелки) и таблица с теми же данными. Тепловая карта клавиш — пять шагов одного синего цвета; шкала проверена на контраст и различимость шагов в обеих темах.

## Тестирование

| Уровень | Что проверяется |
|---|---|
| Модульные тесты движка | Ввод, автомат урока, метрики, формулы уверенности, открытие клавиш, генератор текста (с фиксированным зерном) |
| «Синтетический наборщик» | `tests/syntheticTypist.ts` имитирует ученика, который со временем печатает быстрее и точнее, и проходит весь английский курс (`tests/course.test.ts`). Проверяет, что все буквы открываются, на одну клавишу уходит не больше 40 уроков, в тексте нет закрытых букв и фокусная клавиша есть хотя бы в половине слов |
| Тесты хранилища | Обе реализации проходят один набор тестов; SQLite — на настоящей базе с миграцией приложения |
| Тесты компонентов | Состояния знака, клавиши, экран практики, карточка новой клавиши, главная, статистика |
| Проверка содержания | В словарях нет запрещённых слов и чужих букв; каждая буква раскладки есть в курсе |
| Ручная проверка | Windows, macOS, Linux; клавиатуры ANSI и ISO |

CI на каждый коммит: линтер, проверка форматирования, проверка типов, тесты. Сборка установщиков — при теге версии (см. «Распространение»).

## Распространение

| ОС | Формат | Замечание |
|---|---|---|
| Windows | Установщик `.exe` (NSIS), для текущего пользователя, без прав администратора | Без сертификата подписи Windows показывает предупреждение SmartScreen |
| macOS | `.dmg` для Apple Silicon и для Intel | Для запуска без предупреждений нужен аккаунт Apple Developer (99 $ в год) |
| Linux | AppImage и `.deb` | — |

**Подпись (решение 12.11.2026):** первый релиз выходит без подписи кода. На macOS приложение подписывается ad-hoc (`bundle.macOS.signingIdentity: "-"`): без этого скачанная сборка для Apple Silicon считается «повреждённой» и не открывается. Ad-hoc подпись не заверена Apple, поэтому при первом запуске нужно разрешить его в «Конфиденциальность и безопасность», а если macOS всё же пишет «повреждено» — снять карантин командой `xattr -cr /Applications/KeyEd.app`. Страница загрузки объясняет, как запустить неподписанное приложение. Подпись можно добавить позже: `tauri-action` берёт сертификаты из секретов репозитория, менять код не нужно.

### Как выпустить версию

1. Поднять версию в `package.json` (её берут `tauri.conf.json` и «О программе») и закоммитить.
2. Создать и отправить тег с той же версией: `git tag v0.2.0 && git push origin v0.2.0`.
3. Workflow `.github/workflows/release.yml` соберёт установщики на Windows, macOS (две архитектуры) и Linux, подпишет обновления и создаст черновик релиза с файлами и `latest.json`.
4. Проверить черновик и опубликовать его. После публикации установленные копии увидят обновление при следующем запуске, а страница загрузки — новые файлы.

Страница загрузки — `site/index.html`, одна страница на русском и английском. Workflow `.github/workflows/pages.yml` публикует папку `site/` на GitHub Pages при каждом изменении. Ссылки на установщики страница берёт из последнего релиза через API GitHub и сама выбирает систему посетителя.
